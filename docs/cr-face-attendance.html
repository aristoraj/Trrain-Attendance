1. Purpose & Scope

What is this Change Request?

This document describes the enhancements made to the existing Face Recognition Attendance System integrated with Zoho Creator. The changes introduce a structured Check-In / Check-Out workflow, improved liveness detection, and live photo capture — making attendance records more complete, auditable, and compliant.

All changes have been implemented and tested in the development environment. This document serves as a formal record of those changes and requests client approval to consider them accepted and live in production.

2. Before vs After — Summary
Existing System (Before)
  • Single scan marks attendance as "Present" — no time recorded
  • No check-out mechanism
  • Liveness required two blinks — slower, more friction
  • No alternative liveness action (blink only)
  • No live photo captured or stored
  • No Action field — liveness method not recorded
  • No way to confirm if trainee attended the full session
  • Duplicate scans silently blocked with no feedback
Enhanced System (After)
  • First scan records Check-In time (HH:MM in IST)
  • Second scan (min. 5 min later) records Check-Out time
  • Liveness now requires only one blink — faster experience
  • Smile added as an alternative liveness action
  • Live face photo captured and attached to attendance record
  • Action field records which liveness action was performed
  • Duration tracking possible via Check-In and Check-Out times
  • Clear user feedback for each scan state

4. Liveness Detection Changes

Change — Blink Count Reduced: 2 Blinks → 1 Blink

Previously, the system required the trainee to blink twice to pass liveness verification. This has been reduced to one blink. The change reduces the time spent on the liveness step and improves the experience for trainees who found the two-blink requirement confusing or slow, while maintaining anti-spoofing reliability.

New — Smile as Alternative Liveness Action

In addition to blinking, trainees can now pass liveness by smiling at the camera. The system automatically detects a genuine smile using facial landmark analysis. The method used (Blink or Smile) is recorded in the Action_field of the attendance record, providing an audit trail of how liveness was verified for each scan.

5. New Attendance Flow — Step by Step
1

Face Detection

Trainee opens the attendance widget on their mobile device. The camera activates and detects a face automatically.

2

Liveness Verification Updated

Trainee performs one blink or smiles at the camera. The system confirms the person is physically present (anti-spoofing). The liveness action is noted for the record.

3

Face Recognition

The verified face is matched against enrolled student photos. The system identifies the trainee and shows their name and match confidence.

4a

Check-In (First Scan of the Day) New

If the trainee has not yet checked in today, the system:
• Marks Attendance = Present
• Records Check_In time (current IST time)
• Sets Action_field = Blink or Smile
• Captures and uploads a Live_Captured_Image (face photo)
• Shows a check-in success banner on screen

4b

Check-Out (Second Scan — min. 5 minutes later) New

If the trainee has already checked in today and at least 5 minutes have passed, the system:
• Records Check_Out time (current IST time)
• Sets Checked Out (Auto_Checkout) = Yes
• Shows a check-out success banner on screen

If the trainee scans within 5 minutes of check-in, they are shown a message: "Checkout available in N minutes."

4c

Already Checked Out (Third Scan or Later)

If the trainee has already completed both check-in and check-out today, the system shows an informational message: "Already checked in & out today." No changes are made to the record.

7. Impact on Existing Data & Workflows

Existing attendance records are not affected. The new fields are additive — historical records simply have these fields blank, which is expected. No existing Zoho Creator workflow, report, or configuration has been removed or changed.

The face recognition matching logic and student enrollment process remain unchanged. Only the post-match attendance recording behaviour has been enhanced.
